# ミラコスタ空室監視ツール

東京ディズニーシー・ホテルミラコスタの**空室状況を24時間自動でチェック**して、
**満室 → 空室**に変わった瞬間だけ LINE に通知するツールです。

```
公式サイトの空室状況を10分ごとに確認
        ↓
前回の状態と比較
        ↓
満室 → 空室 に変わった部屋だけを検出
        ↓
LINE に通知（URL 付き）
        ↓
通知をタップして公式予約ページを開く
        ↓
自分の手で予約する
```

> **予約の自動確定は一切行いません。**
> CAPTCHA 突破・bot 検知回避・アクセス制限回避もしません。
> robots.txt を毎回確認し、禁止されていればチェック自体を行いません。

## 1. このシステムで何ができるか

| できること           | 説明                                                         |
| -------------------- | ------------------------------------------------------------ |
| 空室の自動監視       | ミラコスタの空室を 10 分ごとに確認します                     |
| 変化したときだけ通知 | 「満室 → 空室」に変わった瞬間だけ LINE が届きます            |
| 重複通知の防止       | 同じ部屋が空きっぱなしでも、通知は最初の1回だけです          |
| 再通知               | 一度満室に戻ってからまた空いたら、もう一度通知します         |
| 部屋ごとの管理       | 「ハーバービューだけ」など、部屋単位で状態を持ちます         |
| 複数条件の同時監視   | 11/20 と 11/21 など、何件でも同時に見張れます                |
| 24時間常駐           | Mac にログインすれば自動で動き、落ちても自動復帰します       |
| 異常の通知           | サイトの作りが変わった／確認できていない時も LINE で教えます |

**できないこと（意図的にやりません）**

- 予約の自動確定
- CAPTCHA の自動突破
- bot 検知・アクセス制限の回避
- 非公開 API の認証突破
- Mac がスリープ中の監視（→ [22章](#22-mac-のスリープについて重要)）

## 2. 必要なもの

- **Mac**（Apple Silicon / Intel どちらでも動きます）
- **Node.js 20 以上**
- **LINE アカウント**（普段使っているもので大丈夫です）
- インターネット接続

まず自分の Mac を確認してみましょう。ターミナル（`アプリケーション → ユーティリティ → ターミナル`）を開いて：

```bash
uname -m
node -v
npm -v
command -v node
```

**正常なら**こんな表示になります：

```
arm64                    ← Apple Silicon なら arm64、Intel なら x86_64
v22.11.0                 ← v20 以上ならOK
10.9.0
/opt/homebrew/bin/node   ← Node.js の場所（人によって違います）
```

**`command not found: node` と出たら** → Node.js が入っていません。次の3章へ。

## 3. Node.js のセットアップ

すでに `node -v` で `v20` 以上が表示された人は、この章は飛ばして構いません。

**Homebrew（Mac の定番パッケージ管理ツール）を使う方法**を推奨します。

```bash
# Homebrew が入っているか確認
brew --version
```

入っていなければ、[https://brew.sh](https://brew.sh) の手順に従ってインストールしてください。

```bash
# Node.js をインストール
brew install node
```

**正常なら**最後に `🍺  /opt/homebrew/Cellar/node/...` のような表示が出ます。

確認：

```bash
node -v
```

`v22.x.x` のように表示されれば成功です。

> **nvm を使っている人へ**
> nvm でも動きますが、常駐サービスにするときは注意が必要です。
> nvm の Node は「バージョンを消すと動かなくなる」ため、
> `npm run install-service` は警告を出します。
> 長期間ほったらかしで動かすなら `brew install node` の方が安定します。

## 4. npm install

このプロジェクトのフォルダに移動して、必要なライブラリを入れます。

```bash
cd ~/miracosta-monitor    # ← このプロジェクトを置いた場所
npm install
```

**これは何をしているのか**
プログラムが使う部品（HTML を読む道具、データベース、ブラウザ自動操作ツールなど）を
`node_modules/` フォルダにダウンロードしています。1〜3分ほどかかります。

**正常なら**最後にこう出ます：

```
added 178 packages in 25s
```

続けて、**ブラウザ（Chromium）を1回だけダウンロード**します。

```bash
npx playwright install chromium
```

**これは何をしているのか**
公式サイトが JavaScript で描画している場合に備えた「予備の取得方法」です。
通常は使いませんが、入れておかないといざという時に `UNKNOWN` しか返せません。
約150MB、2〜5分かかります。

**正常なら** `Chromium ... downloaded to ...` と表示されます。

> `npm install` だけでは入らないことがあります。必ずこのコマンドも実行してください。

**失敗したら**

- `EACCES` → 権限エラー。`sudo` は使わず、フォルダの場所を `~/` の下に変えてください
- ネットワークエラー → Wi-Fi を確認してもう一度

次に、初期セットアップを実行します。

```bash
cp .env.example .env
npm run setup
```

**これは何をしているのか**

- `data/` `logs/` `debug/` フォルダを作る
- `config/watch.json`（監視条件ファイル）を雛形から作る
- Node.js のバージョンを確認する
- LINE の設定ができているか確認する
- Chromium（予備の取得方法）が入っているか確認する
- 公式サイトの robots.txt を読んで、アクセスしてよいか確認する

**正常なら**チェックリストが並び、最後に「Next steps」が出ます。
この時点では LINE がまだ未設定なので `⚠️` が出て正常です。次の5章へ進みます。

## 5. LINE 公式アカウントを作る

LINE の通知は「あなた専用の bot」から届きます。そのための準備です。

1. ブラウザで [https://developers.line.biz/console/](https://developers.line.biz/console/) を開く
2. 「**LINEアカウントでログイン**」をクリックし、普段の LINE アカウントでログイン
3. 初回は開発者名とメールアドレスの登録を求められるので入力する

**正常なら**「コンソール」画面が表示されます。

---

## 6. LINE Developers の設定

1. 画面の「**プロバイダー**」欄で「**作成**」をクリック
2. プロバイダー名を入力（例：`mizuki-personal`）— 何でも構いません
3. 「作成」をクリック

**これは何をしているのか**
「プロバイダー」は bot をまとめる入れ物です。中身はこれから作ります。

**正常なら**作ったプロバイダーの画面に移動します。

---

## 7. Messaging API の設定

1. プロバイダーの画面で「**新規チャネル作成**」をクリック
2. 「**Messaging API**」を選ぶ
3. 必須項目を埋める：
   - チャネル名：`ミラコスタ監視`（好きな名前でOK）
   - チャネル説明：`空室通知`
   - 大業種／小業種：適当に選んで大丈夫です
   - メールアドレス：自分のもの
4. 利用規約に同意して「作成」

**正常なら**チャネルの管理画面が開きます。

**次に、自分の bot を友だち追加します（これを忘れると通知が届きません）**

1. 「**Messaging API**」タブを開く
2. 「**QRコード**」が表示されているので、スマホの LINE で読み取る
3. 友だち追加する

---

## 8. Channel Access Token を取得する

1. チャネル管理画面の「**Messaging API**」タブを開く
2. いちばん下までスクロールして「**チャネルアクセストークン（長期）**」を探す
3. 「**発行**」をクリック
4. 表示された長い文字列を**コピー**する

**これは何なのか**
「このプログラムがあなたの bot として喋ってよい」という許可証です。
**パスワードと同じ**なので、絶対に他人に見せたり、Git に保存したりしないでください。

**正常なら**200文字くらいの英数字の羅列が表示されます。

## 9. 誰に通知するかを決める

ここは**自分以外にも通知したい場合につまずきやすい**ところなので、仕組みから説明します。

### まず知っておくこと

LINE の `push` API は「**この1人に送る**」という命令です。
だから送り先に入っていない人には、その人が bot を友だち追加していても届きません。

そして重要な制約があります：

> **友だちのユーザーIDは、LINE Developers の管理画面では見られません。**
> 管理画面に出るのは「**あなた自身の**ユーザーID」だけです。
> 他人のIDを知るには Webhook サーバー（公開URL）が必要で、個人ツールには重すぎます。

そこで、このツールは **2つの方法** を用意しています。

---

### 方法A：ブロードキャスト（**自分以外にも送るならこれ**）

**bot を友だち追加した人全員**に送ります。**ユーザーIDは一切不要**です。

`.env` にこう書くだけ：

```
LINE_BROADCAST=1
```

（`LINE_TO` は空のままで構いません）

**友だちに受け取ってもらう手順**

1. LINE Developers の「**Messaging API**」タブを開く
2. そこに出ている **QRコード** を友だちに見せる／画像を送る
3. 友だちがスマホの LINE で読み取って**友だち追加**する
4. 以上。`.env` の変更は不要です

**注意**：QRコードを知っている人が追加すれば**誰でも**通知を受け取れます。
SNS などに公開しないでください。

---

### 方法B：ユーザーIDを列挙する（自分だけ、または相手のIDが分かる場合）

**自分のIDの調べ方**

1. チャネル管理画面の「**チャネル基本設定**」タブを開く
2. いちばん下までスクロールして「**あなたのユーザーID**」を探す
3. `U` で始まる33文字の文字列をコピーする

**正常なら** `U1234567890abcdef1234567890abcdef` のような形です。

`.env` に書きます（複数ならカンマ区切り）：

```
LINE_TO=U1234567890abcdef1234567890abcdef
```

```
LINE_TO=U1234567890abcdef1234567890abcdef,Ufedcba9876543210fedcba9876543210
```

> 2人以上を指定すると、自動的に `multicast`（1回のAPI呼び出しで複数人に配信）に
> 切り替わります。人数分アクセスするわけではありません。

**グループトークに送ることもできます**（IDは `C`、複数人トークは `R` で始まります）。
ただしこれらのIDも Webhook 経由でしか取得できません。

---

### どちらを選べばいいか

| やりたいこと                       | 設定                                               |
| ---------------------------------- | -------------------------------------------------- |
| 自分だけに通知                     | `LINE_TO=<自分のID>`                               |
| **自分＋友だちに通知**             | **`LINE_BROADCAST=1`**（友だちはQRで追加するだけ） |
| 相手のユーザーIDが既に分かっている | `LINE_TO=<ID1>,<ID2>`                              |

### 送信数のカウントについて

LINE 公式アカウントの無料プランには月あたりの送信上限があり、
**宛先の人数分カウントされます**（2人なら1通の通知で2カウント）。
このツールは「満室→空室」に変わったときしか送らないので通常は問題ありませんが、
気になる場合は `npm run history` で送信回数を確認してください。

## 10. .env を作る

コピーした2つの値をファイルに書き込みます。

```bash
cp .env.example .env    # 4章で実行済みならスキップ
open -e .env            # テキストエディットで開く
```

開いたファイルを、8章と9章で決めた内容で埋めてください。

**自分＋友だちに通知する場合（9章の方法A）**

```
LINE_CHANNEL_ACCESS_TOKEN=ここに8章でコピーした長い文字列
LINE_BROADCAST=1
```

**自分だけ、またはIDを列挙する場合（9章の方法B）**

```
LINE_CHANNEL_ACCESS_TOKEN=ここに8章でコピーした長い文字列
LINE_TO=ここに9章でコピーしたUで始まるID
```

**注意点**

- `=` の前後にスペースを入れない
- 値をクォート（`"`）で囲まない
- 保存を忘れずに（`⌘S`）

**安全性について**
`.env` は `.gitignore` に登録済みなので、**Git には絶対に保存されません**。
ログにもトークンは出ません（出力前に自動でマスクされます）。

## 11. 監視条件を設定する

「いつ・何人で・どの部屋を見張るか」を決めます。

```bash
open -e config/watch.json
```

初期状態はこうなっています：

```json
{
  "settings": {
    "intervalMinutes": 10,
    "notifyOnInitialAvailability": true
  },
  "watches": [
    {
      "id": "miracosta-2026-11-20",
      "hotel": "miracosta",
      "checkIn": "2026-11-20",
      "nights": 1,
      "adults": 2,
      "children": 0,
      "roomKeywords": ["ポルト・パラディーゾ・サイド", "ハーバービュー"],
      "enabled": true
    },
    {
      "id": "miracosta-2026-11-21",
      "hotel": "miracosta",
      "checkIn": "2026-11-21",
      "nights": 1,
      "adults": 2,
      "children": 0,
      "roomKeywords": [],
      "enabled": true
    }
  ]
}
```

### watches の各項目

| 項目           | 意味                                          | 例                       |
| -------------- | --------------------------------------------- | ------------------------ |
| `id`           | 条件の名前（重複禁止・英数字と `-` `_` `.`）  | `"miracosta-2026-11-20"` |
| `hotel`        | ホテル。今は `"miracosta"` を使ってください   | `"miracosta"`            |
| `checkIn`      | 宿泊日（**必ず `YYYY-MM-DD`**）               | `"2026-11-20"`           |
| `nights`       | 泊数（1〜5）                                  | `1`                      |
| `adults`       | 大人の人数（1〜6）                            | `2`                      |
| `children`     | 子どもの人数（0〜6）                          | `0`                      |
| `rooms`        | 部屋数（省略可、既定 1）                      | `1`                      |
| `roomKeywords` | 部屋の絞り込み（**すべて含む** 部屋だけ通知） | `["ハーバービュー"]`     |
| `planKeywords` | プランの絞り込み（省略可）                    | `[]`                     |
| `enabled`      | `false` にすると設定を残したまま停止          | `true`                   |

**`roomKeywords` の使い方がいちばん大事です**

```json
"roomKeywords": []
```

→ **ミラコスタのどの部屋が空いても通知**（いちばん取りこぼしがない設定）

```json
"roomKeywords": ["ハーバービュー"]
```

→ 部屋名に「ハーバービュー」が含まれる部屋だけ通知

```json
"roomKeywords": ["ポルト・パラディーゾ・サイド", "ハーバービュー"]
```

→ **両方とも**含む部屋だけ通知（AND 条件です。OR ではありません）

> キーワードは全角・半角を区別しません。
> 迷ったら `[]`（全部通知）から始めるのがおすすめです。

### settings の各項目

| 項目                          | 既定値   | 意味                                                 |
| ----------------------------- | -------- | ---------------------------------------------------- |
| `intervalMinutes`             | `10`     | 確認の間隔（分）。**5未満は設定できません**          |
| `jitterPercent`               | `15`     | 間隔のばらつき（負荷を集中させないため）             |
| `minRequestSpacingSeconds`    | `20`     | どのリクエスト同士も最低これだけ空ける               |
| `backoffBaseMinutes`          | `5`      | エラー時の待ち時間の最初の値                         |
| `backoffMaxMinutes`           | `60`     | エラー時の待ち時間の上限                             |
| `notifyOnInitialAvailability` | `true`   | 初回チェックで既に空室なら通知するか                 |
| `staleAfterMinutes`           | `30`     | 何分成功しなければ「異常」と判断するか               |
| `parserErrorThreshold`        | `3`      | 何回連続で解析失敗したら異常とするか                 |
| `transport`                   | `"auto"` | 取得方法（`auto` のままで大丈夫です）                |
| `respectRobotsTxt`            | `true`   | robots.txt を守るか。**`true` のままにしてください** |

**編集したあとは必ず**：

```bash
npm run status     # 設定が読めているか確認
```

JSON の書き間違い（カンマ忘れなど）があると、ここでエラー内容が表示されます。

## 12. LINE のテスト

```bash
npm run test-line
```

**これは何をしているのか**
設定した2つの値を使って、あなたの LINE にテストメッセージを1通送ります。
空室確認は一切しません。

**正常なら**ターミナルに：

```
Sending to: broadcast — everyone who added the bot as a friend

✅ Sent. Check LINE on every phone that should receive alerts.
```

`Sending to:` の行で**誰に送られるか**が確認できます。
ここが `1 person` なのに2人に届けたいなら、9章の方法Aに切り替えてください。

そしてスマホの LINE に：

```
🏰 Miracosta Monitor

LINE通知テスト成功
```

**失敗したら**

| エラー                             | 原因と対処                                                                                                                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LINE is not configured`           | `.env` が無い／値が空。10章をやり直す                                                                                                                                  |
| `HTTP 401` `Invalid access token`  | トークンが違う・途中で切れている。8章で再発行してコピーし直す                                                                                                          |
| `HTTP 400`                         | `LINE_TO` のIDが違う。9章で「あなたのユーザーID」を確認（`U` で始まる）                                                                                                |
| 送信は成功するのに届かない         | **bot を友だち追加していません**。7章の QR コードを読み取る                                                                                                            |
| **自分には届くが友だちに届かない** | 送信先に友だちが入っていません。`.env` に `LINE_BROADCAST=1` を設定し、友だちにQRコードで bot を友だち追加してもらう（9章の方法A）。設定後は `npm run restart-service` |

## 13. 1回だけ空室確認する

```bash
npm run check
```

**これは何をしているのか**
`config/watch.json` の各条件について、公式サイトを**1回だけ**確認します。
結果を画面に出し、状態をデータベースに保存し、
「満室 → 空室」になっていれば LINE も送ります（本番と全く同じ動作です）。

**正常（満室のとき）**：

```
Miracosta Monitor

----------------------------------------
Watch:
miracosta-2026-11-20

Checking:
```

## 22. Mac のスリープについて（重要）

> ### ⚠️ **MacBook の蓋を閉じてスリープしている間は監視できません。**

これは仕様ではなく、macOS の仕組み上そうなります。スリープ中は
プロセスが止まるため、その間に出た空室は検知できません。

### 復帰したときの動作

スリープから復帰すると：

1. 長時間の空白を検知してログに記録します
2. **ネットワークが戻るまで待ちます**（最大5分）
3. 各条件について**1回だけ**最新状態を確認します

**寝ていた分をまとめて何十回もアクセスすることはありません。**

### 24時間動かしたい場合の選択肢

**方法1：電源につないで、スリープしない設定にする（おすすめ）**

1. `システム設定` → `バッテリー` → `電源アダプタ`
2. 「**ディスプレイがオフのときはMacを自動でスリープさせない**」をオン

さらに蓋を閉じても動かしたい場合は、外部ディスプレイ／キーボードを接続する（クラムシェルモード）か、
Mac mini など据え置き機を使ってください。

**注意点**

- 電源アダプタを必ず接続してください（バッテリー運用だと数時間で切れます）
- 発熱するので、風通しのよい場所に置いてください

**方法2：一時的にスリープを防ぐ**

数時間だけ集中して見張りたいとき（キャンセル拾いを狙う朝など）：

```bash
caffeinate -i npm run monitor
```

**これは何をしているのか**
`caffeinate -i` は「このコマンドが動いている間はスリープしないで」と
macOS に伝える標準コマンドです。`Control + C` で終了すれば元に戻ります。

> このツールは `caffeinate` を**強制しません**。常時スリープを禁止すると
> バッテリーと発熱に影響するため、使うかどうかはあなたが選んでください。

## 25. トラブルシューティング

### LINE が届かない

```bash
npm run test-line
```

まずこれで切り分けます。

- テストも届かない → 12章の表を確認（多くは**友だち追加忘れ**）
- テストは届くのに空室通知が来ない → そもそも空室が出ていない可能性大。
  `npm run history` で `available` が記録されているか確認

### `Current state: UNKNOWN` が続く

公式サイトのページ構造が変わった可能性があります。
**満室と誤判定はしていません**（空室を見逃さない側に倒しています）。

3回連続で解析に失敗すると、LINE にこの警告が届きます：

```
⚠️ ミラコスタ監視システム異常
公式予約サイトの構造が変更された可能性があります。
空室判定を安全に停止しました。
```

**まず `Detail:` 行を読んでください。** 取得方法ごとの理由が `|` で区切って出ます：

```
Detail:
http: Page did not contain room rows... | playwright: Could not start Chromium...
```

`http:` の側が本当の原因です（`playwright:` 側は予備の取得方法の話）。

**調べ方**：

```bash
npm run capture
```

**これは何をしているのか**
実際のページを1回取得して、①パーサーがどう読んだか を表示し、
②**秘密情報を除去した**ページの控えを `tests/fixtures/` に保存します。

出力に室名や価格が並んでいれば読めています。
`parser outcome: parser_error` なら、`src/parser/signals.ts` の
日本語フレーズ一覧を更新する必要があります。

保存されたファイルには Cookie・トークン・入力値・個人情報は含まれません。

### `Could not start Chromium` / `Executable doesn't exist` と出た

予備のブラウザがインストールされていません。1回だけ実行してください。

```bash
npx playwright install chromium
npm run check
```

**なお、このエラーが出たということは、通常のHTTP取得では読めなかったということです。**
Chromium を入れて再実行しても `UNKNOWN` のままなら、次の項目へ進んでください。

### `STOPPED (bot-check page detected)` と出た

公式サイトが CAPTCHA やアクセス確認画面を出しました。
**このツールは絶対に突破しません。** その条件の監視を止め、LINE に1回だけ警告します。

**やること**：

1. ブラウザで公式予約サイトを普通に開いてみる
2. 自分でも同じ画面が出るなら、しばらく時間を置く
3. 普通に見られるようになったら再開：
   ```bash
   npm run restart-service
   ```
4. 何度も起きるようなら `config/watch.json` の `intervalMinutes` を
   `15` や `20` に増やしてください

### `CHECK_FAILED` が続く

ネットワークかサイト側の一時障害です。自動的に間隔を空けて再試行します
（5分 → 10分 → 20分 → 40分 → 最大60分）。正常に戻れば自動で10分間隔に戻ります。

30分以上成功しないと、LINE にこの警告が届きます：

```
⚠️ ミラコスタ監視異常
最後に正常確認できてから30分以上経過しています。
```

復旧すると `✅ ミラコスタ監視復旧` が1回だけ届きます。

**確認すること**：Wi-Fi が繋がっているか、Mac がスリープしていなかったか。

### サービスが起動しない

```bash
npm run status
tail -50 logs/launchd.err.log
```

よくある原因：

| 症状                                                 | 対処                                 |
| ---------------------------------------------------- | ------------------------------------ |
| Node.js のパスが変わった（nvm でバージョン変更など） | `npm run install-service` をやり直す |
| `dist/index.js` が無い                               | `npm run build`                      |
| 設定ファイルの JSON エラー                           | `npm run status` でエラー内容を確認  |

### プロジェクトを別の場所に移動した

launchd には移動前の絶対パスが登録されています。移動したら必ず：

```bash
npm run install-service
```

をやり直してください（自動で新しいパスに書き換わります）。

### 全部やり直したい

```bash
npm run uninstall-service
rm -rf data/ logs/ debug/ node_modules/ dist/
npm install
npm run setup
```

`.env` と `config/watch.json` は残るので、設定し直す必要はありません。

## 付録A：サイトへの配慮とルール

このツールは、公式サイトに迷惑をかけないことを**最優先**に作られています。

| やっていること     | 内容                                                      |
| ------------------ | --------------------------------------------------------- |
| robots.txt の遵守  | 毎回確認し、禁止パスならチェックを行いません              |
| Crawl-delay の遵守 | 宣言があれば、設定値より優先して間隔を空けます            |
| 控えめな頻度       | 既定10分間隔。**5分未満は設定できません**（コードで拒否） |
| リクエストの直列化 | 複数条件があっても同時アクセスせず、最低20秒空けます      |
| ゆらぎ             | 毎回きっかり同じ秒に叩かないよう ±15% ばらつかせます      |
| 指数バックオフ     | エラー時は 5→10→20→40→最大60分と間隔を広げます            |
| 混雑ページの尊重   | 「アクセスが集中しています」を検知したら判定せず待ちます  |
| 1条件1リクエスト   | ホテル全体を1回取得し、部屋の絞り込みは手元で行います     |

**やらないこと**

- CAPTCHA の自動突破（検知したら**停止**します）
- bot 検知・アクセス制限の回避
- ログインが必要な情報の取得
- 非公開 API の署名・認証の突破
- 予約の自動確定

**アクセス頻度について**：この用途（1日あたり数百リクエスト、常に20秒以上の間隔）は、
人が手動でページを更新するのと同程度の負荷です。心配なら `intervalMinutes` を
15〜30 に増やしてください。

## 付録B：空室判定の仕組み

### 何を見て判定しているか

公式サイトの検索結果ページには、部屋ごとに
`hotelRoomCd=HOTDHM...` という**公式の部屋コード**を含むリンクが並びます。
このコードを部屋の識別子（キー）として使い、各行について：

- 「満室」「×」「受付終了」などが書かれている → **その部屋は満室**
- 価格（`¥128,000`）や「予約する」「残り1室」がある → **その部屋は空室**
- どちらとも読めない → **判定しない**

### 一番大事なルール

```
「満室」と判断するのは、
サイトがはっきりそう言っているときだけ。
```

ページが読めなかった、形が変わった、通信が失敗した——
そういうときは必ず `UNKNOWN` になります。**満室と決めつけません。**

これは「空室を見逃さない」ためです。誤って「満室」と記録すると、
次に読めたときに「満室→空室」の偽の通知が出るうえ、
本当の空室のタイミングを逃す危険があります。

### 通知するタイミング

部屋ごとに前回の状態と比べて、**空室でなかったものが空室になったときだけ**送ります。

```
12:00 満室      →  通知しない
12:05 満室      →  通知しない
12:10 空室      →  🔔 通知
12:15 空室      →  通知しない（重複防止）
12:20 空室      →  通知しない
12:30 満室      →  通知しない（状態だけ更新）
12:40 空室      →  🔔 再通知
```

`UNKNOWN` のときは状態を**書き換えません**。
そのため通信障害のあと空室が続いていても、二重通知にはなりません。

**LINE が送れなかったときは**、その部屋に「未送信」の印が残り、
次回のチェックで自動的に再送されます。**通知が消えてなくなることはありません。**

### 取得方法の選び方

```
① 普通の HTTPS リクエスト（軽い・サイトに優しい）  ← まずこれ
        ↓ 読めなければ
② 本物の Chromium で同じ公開 URL を開く（重い）
```

`transport: "auto"` なら自動で切り替わり、1時間ごとに①へ戻そうと試みます。
どちらの場合も**同じ公開 URL** にアクセスし、回避行為は一切しません。

## 付録C：公式サイトの調査結果

実装前に調べた内容です。

| 項目                           | 結果                                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 空室確認画面                   | `https://reserve.tokyodisneyresort.jp/hotel/list/`（検索フォームは `/hotel/search/`）                                           |
| ログインの要否                 | **空室の閲覧にログインは不要**。MyDisney ログインが要るのは実際に予約するときだけ。このツールはログインしません                 |
| URL パラメータ指定             | **可能**。`useDate`（`YYYYMMDD`）、`stayingDays`、`adultNum`、`childNum`、`roomsNum`、`searchHotelCD` などを GET で指定できます |
| ミラコスタのホテルコード       | `searchHotelCD=DHM`（他：`TDH` ランドホテル、`DAH` アンバサダー、`TSH` トイ・ストーリー）                                       |
| 通常の HTTP で取得可能か       | **可能な想定**。検索結果ページは公開されており、検索エンジンにも索引されています                                                |
| JavaScript / Playwright の要否 | **必須ではない**想定。HTTP で読めない場合のみ Chromium にフォールバックします                                                   |
| 部屋の一意な ID                | **あります**：`hotelRoomCd`（例 `HOTDHMSPB0001N`）。これを部屋キーに使います                                                    |
| 取得できる情報                 | 部屋名、サイド、景観、料金、部屋コード、空室/満室                                                                               |
| 空室・満室の判定材料           | 部屋行のテキスト（「満室」「×」／価格・「予約する」）と、結果なしメッセージ                                                     |
| bot 対策                       | 配信は Akamai。混雑時やアクセス過多で確認画面が出る可能性があります。**検知したら停止します**                                   |
| robots.txt                     | **実行時に毎回取得して従います**（`respectRobotsTxt: true`）。禁止なら監視しません                                              |
| 推奨する監視頻度               | **10分間隔**（最低5分をコードで強制）                                                                                           |

> **正直にお伝えする注意点**
> このツールを開発した環境からは、`reserve.tokyodisneyresort.jp` へ直接接続できませんでした
> （Akamai がデータセンター／国外 IP からの接続を落とすため）。
> そのため上の内容は、**公開されている URL 構造・パラメータ・部屋コードの実例**から組み立てています。
> あなたの Mac（日本の家庭回線）からは問題なく繋がるはずです。
>
> **最初に必ず `npm run capture` を実行してください。**
> 実ページをパーサーがどう読んだかが表示され、ズレがあればすぐ分かります。
> `tests/fixtures/` の HTML も、開発時に手で書いた見本です（本物ではありません）。
> `npm run capture` を実行すると、本物から作った控えに置き換えられます。

## 付録E：今の制約

| 制約                         | 内容                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| スリープ中は動かない         | Mac がスリープしていると監視できません（[22章](#22-mac-のスリープについて重要)）                 |
| 検知は最短でも設定間隔       | 10分間隔なら、空室が出てから最大10分遅れます                                                     |
| 予約はしません               | 通知を見て、自分の手で予約してください                                                           |
| サイト構造への依存           | 公式サイトが大きく変わると解析できなくなります（そのときは `UNKNOWN` になり、LINE で警告します） |
| 実ページ未検証               | パーサーは公開情報から組み立てています。初回に `npm run capture` で確認してください              |
| ログイン専用情報は取れません | 会員限定プランなど、ログインが必要な情報は対象外です                                             |
| ミラコスタ以外               | 他ホテルのコードは用意済みですが、動作確認はミラコスタのみです                                   |
